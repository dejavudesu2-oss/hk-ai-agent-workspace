## 1. Architectural Strategy: Restart from Scratch vs. Resume

- **Core Reality**: Public LLM inference APIs (OpenAI, DeepSeek, SiliconFlow) operate over stateless HTTP SSE streams (`POST /chat/completions`). No upstream provider supports stateful session resumption (e.g., "resume stream from token 450").
- **Strategy Adopted**: **Automatic Clean Restart on Secondary Upstream**.
  When the primary provider (`DeepSeek`) encounters:
  - Immediate failure: HTTP 429 (Rate Limit) or HTTP 503 (Overloaded)
  - Latency stall: Timeout exceeded (configurable threshold, default 15s; test harness 80ms)
  - Mid-stream network abort: Socket disconnect, TCP RST, or `Connection reset by peer`
  
  The `RealLLMProvider` automatically aborts the primary stream reader and initiates a fresh request to the secondary upstream (`SiliconFlow / Qwen2.5-Coder`) with the full conversation prompt context.

## 2. Token Accounting: What Happens to Tokens Already Paid For?

- **Upstream 1 Sunk Tokens**:
  Tokens generated by the primary provider before connection reset were already computed and billed by the upstream server.
  Our `RealLLMProvider` accumulates all token chunks parsed from `data: {... "usage": {...}}` into the local `CostGuard` daily spend ledger (`recordSpendUSD()`). These sunk tokens count toward the daily budget cap ($0.50 USD limit) to guarantee that upstream network flapping cannot cause a financial overrun.
- **Upstream 2 Fresh Tokens**:
  The secondary upstream bills for a complete new generation from prompt token 0 to completion. Sunk tokens cannot be refunded or spliced.

## 3. Virtual File System (VFS) State & Integrity

How does the client or server prevent duplicate or corrupted partial files when a stream drops mid-flight?

1. **Path-Keyed Map Invariant**:
   The VFS is an in-memory `Map<string, ParsedFile>`. Files are identified strictly by normalized file path (e.g. `src/app.js`). Because Map keys are unique, re-emitting files never creates duplicate file entries in the tree.
2. **In-Flight Discard on Tag Start**:
   When the primary stream breaks while emitting `src/app.js`, the buffer contains half-written code (`const halfWritten = 123;`).
   When the secondary stream takes over and emits `<sandbox_action type="file" path="src/app.js">`, `StreamingActionParser` executes:
   ```ts
   this.currentFilePath = filePath;
   this.currentFileContent = '';
   ```
   This resets the accumulation buffer to empty. When the complete content is delivered and closed with `</sandbox_action>`, the file in the VFS is overwritten with the 100% clean, valid file.
3. **Dual Failure Termination**:
   If both primary and secondary upstreams fail, the stream terminates with `[Error: Stream interrupted and all backup upstreams failed.]`. The in-flight file is marked `isTruncated = true`, and the UI blocks live preview execution to prevent rendering syntax-broken apps.
