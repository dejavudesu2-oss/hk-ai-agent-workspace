## 1. Architectural Decision: Virtual Document + Babel Standalone vs. Sandpack

### Options Evaluated:
1. **CodeSandbox Sandpack (`@codesandbox/sandpack-react`)**:
   - *Pros*: Built-in multi-file bundler UI.
   - *Cons*:
     - **Commercial Licensing Trap**: CodeSandbox restricted Nodebox runtimes under a proprietary EULA requiring commercial licensing agreements.
     - **Heavy Footprint**: Adds >15MB in npm dependencies and heavy React bundle bloat.
     - **COOP/COEP Network Restrictions**: Requires `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` headers, which completely breaks Stripe hosted payment embeds, third-party avatar CDNs, and Google fonts.
     - **Vendor Dependency**: Relies on CodeSandbox CDN packager availability.
2. **Virtual Document In-Browser Bundler + Babel Standalone (Chosen)**:
   - *Pros*:
     - **100% Free & Open**: Zero licensing royalty or legal risk.
     - **Zero Server Cost**: Transpiles and renders in-browser via Blob / `srcDoc` with <50ms compile time.
     - **No COOP/COEP Headaches**: Stripe checkout, Google fonts, and external assets work seamlessly.
     - **Self-Contained**: Works offline or on local networks with zero external vendor telemetry.
   - *Cons*: Not intended for running server-side Node.js C++ native modules in browser; such backend workloads are cleanly offloaded to Tier 2 gVisor containers.

**Final Decision**: Virtual Document + Babel Standalone is adopted as the Tier 1 in-browser rendering engine. Recorded in `loop/DECISIONS.md`.

## 2. Sandboxed Iframe Security Model

### 2.1 The `sandbox` Attribute Configuration
The live preview `<iframe>` is configured strictly with:
```html
<iframe
  srcDoc="..."
  sandbox="allow-scripts allow-modals allow-forms"
/>
```

#### Why `allow-same-origin` is STRICTLY PROHIBITED:
- When an iframe has BOTH `allow-scripts` and `allow-same-origin`, an untrusted script generated by an LLM could access `window.parent.document`, extract auth tokens or cookies, or rewrite the parent application DOM.
- By **omitting `allow-same-origin`**, modern browsers assign the `srcDoc` iframe a unique, opaque **`null` origin** (`origin: "null"`).
- Any attempt by user-generated code to read `window.parent.document` or `window.parent.localStorage` immediately triggers:
  `DOMException: Blocked a frame with origin "null" from accessing a cross-origin frame.`

### 2.2 Content-Security-Policy (CSP)
Every generated preview document injects a strict CSP meta header:
```html
<meta http-equiv="Content-Security-Policy" content="default-src 'self' 'unsafe-inline' 'unsafe-eval' data: blob: https://cdn.tailwindcss.com https://unpkg.com; img-src * data: blob:; connect-src *;">
```
- Restricts external script sources strictly to trusted public CDNs (Tailwind CSS, React 18, Babel Standalone).
- Prevents unauthorized malicious iframe script downloads while permitting user-written inline scripts and dynamic JS evaluation.

### 2.3 PostMessage Watchdog Error Protocol
The preview injects a lightweight error interceptor:
```javascript
window.onerror = function(msg, url, line, col, error) {
  window.parent.postMessage({
    type: 'WATCHDOG_ERROR',
    message: String(msg) + ' (line ' + line + ':' + col + ')'
  }, '*');
};
```
Because `window.parent.postMessage` is explicitly permitted for opaque `null` origins by browser standards, runtime exceptions and unhandled promise rejections are reliably communicated to the parent UI without compromising isolation. The parent display shows the "一鍵 AI 修復" (One-Click AI Repair) button to feed the traceback back to the LLM.

## 3. Verification Protocol

### Automated Verification
Run `npm test`:
- `src/__tests__/preview.test.ts` validates:
  1. Safe string inlining without `$n` replacement corruption.
  2. Regex path escaping.
  3. Todo app HTML/CSS/JS code generation and CSP injection.
  4. Omission of `allow-same-origin` from iframe sandbox attribute.

### Manual Verification Steps
1. Run `npm run dev`.
2. Open `http://localhost:3000` in Google Chrome or Firefox.
3. Click the sample prompt: "build me a todo app" or type it in the chat panel.
4. Observe files streaming into the Monaco Editor.
5. In the right preview pane, verify that the Todo list renders with Tailwind styling, input box, and "Add" button.
6. Type a new todo item (e.g., "Buy milk in Central") and click Add; verify the item appears in the list.
7. Open DevTools Console: verify that `iframe.contentWindow.parent.document` access is blocked with a cross-origin SecurityError.
